## Tradeoffs
- 2026-09-10T13:21:00Z — ECS Fargate over Lambda: Lambda would save idle cost at this modest load, but the modular monolith relies on in-process ports (shared AuthzService, session validation, in-process event bus) whose hot-path designs assume a long-lived process; splitting per-unit into Lambdas would fragment those seams and re-introduce the coupling the units deliberately avoid. Fargate keeps one deployable, preserves parity, and right-sizes cheaply (Graviton/arm64, scale-to-2 baseline).
- 2026-09-10T13:21:00Z — DynamoDB over RDS/Postgres for the request store: the access pattern is single-key read + append write + version conditional; DynamoDB gives per-key optimistic concurrency natively (ConditionExpression on version), PITR for the 7-year audit feed, and Streams for the transactional outbox — a relational engine would add join/ORM machinery the bounded aggregate does not need. Trade-off: rich cross-request queries are owned by status-tracking, which can layer a GSI or its own read model.
- 2026-09-10T13:21:00Z — On-demand DynamoDB capacity for dev/staging and provisioned+autoscaling for production baseline, balancing cost (no idle provisioned spend in non-prod, seasonal-burst absorption) against predictable prod cost.
